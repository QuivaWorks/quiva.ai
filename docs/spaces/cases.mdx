A **case** is a record that holds one piece of work for a client: a project, a service request, an
application. It has its own page, and its own files and tasks, so everything about that piece of
work sits in one place under the client.

<Note>
Cases are set up per space. Which case types your space offers, what they are called, and the
stages they move through are as configured for your space. If a space has not declared any, it
uses a single default type labelled **Case**.
</Note>

## Case types

A space declares its case types in its configuration. Each type says:

| Setting | What it controls |
|---|---|
| Label | What the case is called in the space, for example "Project" or "Service request". |
| Stages | The records a case moves through, each with its own label and icon. |
| Heading | The fields that make up the case's title. |
| From document | Optional. How a dropped document starts or refreshes a case of this type. See [Starting or refreshing a case from a document](#starting-or-refreshing-a-case-from-a-document). |

Names, stages and icons are not fixed. Two spaces can offer different case types, and a space can
offer several.

## Starting a case

Starting a case happens from the client it belongs to, using the button your space has set up for
it.

<Steps>
  <Step title="Start the case">
    Choose the button for the case type you want. If you started it from a place that does not
    already belong to a client, a **Whose is this?** dialog opens first. Click the client the case
    belongs to.
  </Step>
  <Step title="Choose how to fill it in">
    If the case type can read a document, a dialog offers a drop zone, and an **Enter details**
    button for filling in the form by hand. Without that option, the form opens directly.
  </Step>
  <Step title="Save">
    The case is created and opens on its own page.
  </Step>
</Steps>

## A case page

A case opens on its own page inside the space. The breadcrumb shows the case under its client, and
the page follows the layout your space gives that case type. A page can hold:

- a heading built from the case type's heading fields
- the case's fields and current stage
- tabs for its files, tasks and history

{/* IMAGE: S14 — a case page */}

### Tabs on a record page

A case page is a record page, and its tabs are not fixed. The tabs you can show are:

**Files**, **Tasks**, **Comments**, **History**, **Records**, **List**, **Versions**, **People**,
**Chats**, **Meetings** and **Notes**.

To change them:

<Steps>
  <Step title="Edit the page">
    Click **Edit** on the record page. While you are editing, **Cancel edit** leaves without
    saving.
  </Step>
  <Step title="Add a tab">
    Click **Add tab** and choose what the tab shows.
  </Step>
  <Step title="Add rows to a side panel">
    In a side panel, click **Add to this panel** to add a row of one of the types above. Removing a
    row leaves its data alone.
  </Step>
</Steps>

## Starting or refreshing a case from a document

When a case type is set up to read documents, you can drop a file instead of typing.

- **To start a case**, open the start dialog and drop the document into the drop zone. Abbie reads
  it and fills in the case from what it finds.
- **To refresh a case**, click the update button on the case page. It is labelled **Update from a
  document** unless your space names it differently. Drop a document and the case's fields are
  brought up to date from it.

You can drop several files at once. If a file cannot be used, the dialog shows why and you can
drop another, or choose **Enter details** to type the case instead.

<Tip>
Check the fields after a document fills them in. Abbie reads what the document says, and you
confirm it before relying on it.
</Tip>
